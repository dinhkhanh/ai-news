# ai-news

Internal app: news article URL → short vertical video → Facebook Reels / TikTok / YouTube Shorts.
Plan of record: `docs/PLAN.md`. Setup runbook: `docs/SETUP.md`. External filings: `docs/REQUESTS.md`.

## Layout
- `apps/web` – Next.js 16 (App Router, `src/`), Better Auth, Drizzle, Inngest, admin CMS at `/admin`.
  - `src/lib/fetch` – extraction chain (Browser Rendering → HTTP → Firecrawl → manual), Readability on linkedom, flags. A provider that errors, is blocked, or returns < 120 words hands over to the next one, in auto mode and in the manual “Lấy lại” re-fetch alike (`fetchOrder`: the picked provider only goes first). “Blocked” = `blocked.ts` `detectBlock` (pure, tested): refusal status (401/403/429/451/503…), interstitial title, vendor challenge markup (Cloudflare, DataDome, PerimeterX, Imperva, AWS WAF, Sucuri, Akamai), wall phrases (en + vi), redirect to a login/consent/captcha URL; all only below 300 extracted words. A wall is never kept as the article; a paywall teaser (< 300 words) stays a candidate while the other providers are tried. `attempts[].blocked` lands in the `article.fetched` activity payload.
  - `src/lib/llm` – Anthropic client (Vault key, spend cap, cost rows), structured-output schemas, template rendering, script / faithfulness / classify calls, topic research (`research.ts` + pure `research-sources.ts`).
  - `src/lib/prompts/defaults.ts` – built-in templates (also seeded by migration 0003); admin versions in `prompt_templates` override them.
  - `src/lib/media` – phase 3: `tts.ts` (Google TTS + STT word timings), `stock.ts` (Pexels/Pixabay), `broll.ts` (per-scene search → Haiku rank → download, shared by build + regenerate), `rank.ts` (Haiku ranks B-roll thumbnails; gated by flag `ai_media`, the integration spend cap and the daily `ai_media` quota), `webvideo.ts` (same-story footage from video sites: media-Lambda `web-video-search` = yt-dlp `ytsearch` + video-page URLs from Firecrawl search, metadata only; `allocate`'s `limit` caps how many shots a set of pool items fills together; tested), `originality.ts` (pure, tested: Meta's unoriginal-content limits on third-party video footage, see Rules → Originality), `watermark.ts` (pure, tested: watermark verdict from Vision readings of a few frames) + `watermark-scan.ts` (frames via the media Lambda `cover`, Cloud Vision `TEXT_DETECTION` + `LOGO_DETECTION`, verdict kept in `assets.meta.watermark`), `vision.ts` (the Cloud Vision client shared with `faces.ts`), `framing.ts` + `faces.ts` (face guard, flag `face_guard`: `faces.ts` runs Cloud Vision `FACE_DETECTION` once per still and keeps size + boxes in `assets.meta.frame`; `framing.ts` is pure and tested: `overlayZones` mirrors the overlay layout of `News.tsx`, `frameStill` picks the crop `focus` (pan, ≤ 1.3 zoom, Ken Burns off if needed) so faces are not cropped, not under text / platform UI, and centred on the upper-third line, else `ok: false`), `music.ts` (Mubert v3 + library), `brand.ts` (kits: `listBrandKits`, `loadBrand(ctx, kitId)` = the project's kit → workspace default → platform look, `chooseBrandKit` = Haiku match of the article against each kit's name / description / keywords with the pure keyword scorer of `brand-match.ts` as fallback; The same handler also ships as a self-hosted HTTP API for a machine on a regular ISP line (office Synology NAS), because YouTube blocks datacenter IPs: `src/server.ts` (bearer token, `GET /health`, `POST /invoke`), `src/server-validate.ts` (tested: only search + trimmed downloads of known video sites, only web-video R2 keys), `Dockerfile.nas` (uses yt-dlp's ffmpeg builds; the static John Van Sickle ffmpeg segfaults on network input on Debian), `build-nas.sh` → `dist/nas/*.tar`. ## Rules
- Output spec is fixed (1080×1920, 30 fps, CRF 18, -14 LUFS). Never trade quality for cost.
- Every user/admin action calls `logActivity`; every paid call calls `recordUsageCost`.
- Org-scoped queries go through `withOrgContext`; admin/cross-workspace through `withServiceContext`.
- Authorisation lives next to the data, never only in a layout: Next renders a page segment without its layout when the request claims the layout is already mounted, and `src/proxy.ts` only looks for a session cookie. Every `/admin` page starts with `await requireAdmin()` and every admin action with `assertAdmin()` (`src/app/admin/page-guards.test.ts` fails otherwise); every `/app` page calls `requireWorkspace` / `requireSession` itself. Better Auth's `/organization/*` endpoints are closed in `hooks.before` except `ORG_ENDPOINTS_OPEN` (members and roles are managed in /admin/workspaces only; `kind` is not client input). A `next` / return parameter goes through `safeNextPath` (`src/lib/url.ts`). Security headers are set for every route in `next.config.ts` (`frame-ancestors 'none'`; there is no script CSP yet).
- Database access (migration 0021): the app is the only client, as role `ai_news_app`; the Supabase Data API roles (`anon`, `authenticated`, `service_role`) hold nothing in `public` and the default privileges no longer give them anything, so do not add supabase-js / REST access without granting on purpose. Every table has RLS on with policies for `ai_news_app` only: a new org-scoped table takes the `<table>_org_isolation` policy (helpers wrapped as `(select app_org_id())` so they run once per statement, because functions with a pinned `search_path` are not inlined), a new platform / auth table takes `<table>_app_only`. `migrations.test.ts` fails on a table without RLS or a policy, a grant to anyone but `postgres` / `ai_news_app`, and a function without `set search_path`.
- Admin CMS pages read through `src/lib/admin-data.ts`: one `SECURITY DEFINER` SQL function per page (migrations 0010 + 0013) returning the page as jsonb with camelCase keys, dates revived in the loader. A round-trip to the pooler is ~50 ms and a `withServiceContext` read costs four, so do not go back to per-table queries there. New functions in `public` must `revoke` from `anon` / `authenticated` / `service_role` by name (Supabase grants them EXECUTE by default, which publishes the function on the REST API) and grant `ai_news_app`; `migrations.test.ts` checks the grants and runs every function.
- The app's Postgres pool (`src/db/index.ts`) runs with `max_pipeline: 0` plus `patches/postgres@*.patch`: postgres.js pipelining through the Supavisor transaction pooler loses replies and hangs pages forever. Keep both when upgrading `postgres`; any new long-lived client on `DATABASE_URL` with `max` > 1 needs the same option.
- Secrets: deployment credentials in Vercel env; admin-editable keys and channel tokens in Supabase Vault (never in tables).
- Inngest v4: triggers in options, `eventType()` for typed events, keep `checkpointing.maxRuntime` below the route `maxDuration`. Set `projects.busy_step` (+ `busy_progress: startProgress()`) when a step is queued, call `reportProgress`/`tickProgress` (`src/lib/progress.ts`) *inside* each `step.run` body, and clear both in the function and in `onFailure`; the UI treats a flag older than 15 min as stale. Pages never poll by re-rendering: `<PipelineStatus>`/`<ProjectsWatcher>` poll `/api/projects/status` and call `router.refresh()` only when the status `rev` changes.
- Queue outages (Inngest, 2026-09-18): the bodies of `fetch-article` and `generate-script` live in `src/lib/pipeline/{fetch,script}.ts` and take a `PipelineSteps` (`steps.ts`): the Inngest function passes `durableSteps(step)`, a direct run passes `directSteps`, so change step logic there, never in the function file, and keep step results JSON-safe. Direct runs (`pipeline/direct.ts`, actions `fetchDirect` / `scriptDirect` / `pasteArticle`, run from `after()`; the project page has `maxDuration = 300`): `claimDirectRun` is a compare-and-set on `busy_progress.at`, allowed when the requested step was never started for `QUEUE_SLOW_MS` (90 s; `queuedForMs` = `at` still equals `startedAt`) or went stale; one provider only (`fetchOrder(method, true)`), no retries, `busy_progress.direct = true`. `<PipelineStatus>` shows `<QueueRescue>` in that state (buttons for `DIRECT_STEPS` = fetch + script; assets / render / publish are too long and can only wait); after a failed direct fetch `projects.inngest_run_id = "direct"` keeps the direct buttons on the fallback card. A manual paste is always a direct run. Every pipeline function's first step calls `eventSuperseded(event.ts, …)` (pure, tested, `project-state.ts`): an event older than the newest result of its step (article / script / `built` timeline / render of the same version + logo), or older than a direct run in progress, returns `{ skipped: "superseded" }` without touching the project, so a backlog draining after an outage redoes nothing (this also skips a dashboard replay of an old event). New pipeline functions need the same check before their first write. Recurring jobs are plain functions in `src/lib/cron-jobs.ts` behind `GET|POST /api/cron/<job>` (`Authorization: Bearer $CRON_SECRET`, closed when unset, 202 + `after()`, `?wait=1` = inline); the scheduler is Supabase pg_cron + pg_net (`infra/supabase/cron.sql`, applied by hand to production on 2026-09-19, not a migration; helper `public.ai_news_cron_call`, secret in Vault as `ai_news_cron_secret`; keep its schedules in sync with `CRON_JOBS`). There are no Inngest crons any more: a cron on Inngest stops with Inngest, and every Inngest run and step is a billed execution (Hobby = 50k / month, and execution *pauses* when it is used up, which looks exactly like an outage). Vercel is on the Hobby plan: a cron more often than daily in `vercel.json` fails the deployment. `queue-watchdog` (`src/lib/queue-health.ts`: `findStalledQueue`, status.inngest.com, one `queue.stalled` activity row + Slack message per 3 h) watches Inngest and must never run on it; /admin/health shows the same two signals.
- Motion graphics (migration 0025): `projects.motion_mode` (`off` | `auto` | `all`, CHECK in SQL) + `motion_engine` (`remotion` | `hyperframes`), chosen in the new-project and “Dựng video” forms (`components/motion-select.tsx`, `parseMotion`). `prepare-assets` runs them right after the voice-over: step `motion-plan` (`all` = every scene; `auto` = `planMotionScenes`, Claude picks at most half the scenes, falling back to the figure heuristic `motionScenes` in the pure, tested `media/motion-plan.ts`), then one step per scene `designMotionShot` against the scene's word timings (`shotWords`); a designed scene is one graphic shot and gets `need` 0 (no picture tiers), a failed design falls back to pictures; everything lands in `build_json.motion`. The editor's inspector has a “Đồ hoạ chuyển động” panel (`motion-panel.tsx`): regenerate `what: "motion"` (engine, instruction, `shot` index or the whole scene) in `regenerate-scene`, which also passes the scene's stills as pictures Claude can see; a spec's words and a composition's HTML are editable in place. `shotsMissing` is 0 for a scene with a graphic. Real footage behind a graphic (composition 0.17.0): both kinds carry `backdrop` (a clip: key, trim, length, credit; null = none) that Remotion plays muted, cover-fitted and looped under the graphic (`MotionBackdrop.tsx`, mood-tinted scrim for `remotion` where `spec.background = "video"` turns it on, a dark scrim and a transparent page for `hyperframes`); the shot's credit is the clip's. The build fetches one stock clip per motion scene by its `brollTerms` (`fetchSceneBroll` keep 1; never for a political story or with `skipStock`) and Claude decides whether to play it (`background: "video"` / `videoBackground: true`); the editor's “Video nền” picks one of the scene's clips (`backdropCandidates`) for the next design (then required) or swaps it in place on an existing graphic. Prompts in `lib/llm/motion.ts` forbid any fact, figure or name the voice-over does not state; HyperFrames output is sanitised (`sanitiseHyperframesHtml`) and checked (`checkHyperframesHtml`: composition id, registered timeline, no wall-clock / random APIs), with one retry naming the problems.
- Claude calls: `claude-opus-5-5` ($4 / $20 per MTok) for script / faithfulness (effort `high`, set explicitly because Opus 5.5 defaults to `medium`) motion graphics (`MODELS.motion`, effort `medium`) and topic research (`MODELS.research`, effort `medium`, see Project sources), all with adaptive thinking (Opus 5.5 cannot turn it off: never send `thinking: { type: "disabled" }` or a forced `tool_choice`, both 400), structured outputs via `client.beta.messages.parse`, cached system blocks and the server-side refusal fallback (`fallbacks: "default"`); `claude-haiku-4-5` for classification. A prompt template's `model` overrides `MODELS` (every stored script / faithfulness template was moved from `claude-opus-5` by migration 0027), so changing the model means a template change too. Map billing/auth/400 errors to `NonRetriableError` (`isPermanentLlmError`).
- Pure helpers that need unit tests live outside `server-only` modules (`src/lib/url.ts`, `fetch/readability.ts`, `llm/render.ts`, `llm/schemas.ts`, `llm/research-sources.ts`, `eval-summary.ts`, `text-match.ts`, `media/{pronounce,align,captions,timeline,visual-plan,framing,originality,watermark}.ts`).
- Timeline JSON stores R2 keys, never URLs; presign only in `timeline-resolve.ts` right before a render (and `presignMap` for the editor preview). Project media lives under `media/<org>/<project>/` (12 mo), raw renders under `tmp/` (24 h), finals under `renders/` or `pinned/`.
- Timeline versions are immutable: never update `timelines.json`; every change goes through `saveTimelineVersion` (new row, `parent_id`, `changes`). Editing the composition's props means editing `packages/video/src/schema.ts` *and* `src/lib/media/editor.ts`/`timeline.ts`; bump `packages/video` and redeploy the site when the composition itself changes (0.3.0 added preview audio + `coverAtSec`; 0.4.0 added `scenes[].shots`; 0.5.0 added the image `focus`; 0.6.0 added the brand overlay: `brand.overlaySrc` / `overlayLayer` + `scenes[].overlay`; 0.7.0 moved the headline to the lower third and added `brand.logoMotion`). Never deploy twice under one version: the site name comes from the version, so a second deploy overwrites the first and there is nothing to roll back to. 0.8.0 added per-kit text settings: `brand.headline` `{ fontSize, x, y }` and `brand.caption.x / y`. Text layout: one function, `textLayout(brand, kind)` in `packages/video/src/schema.ts`, used by `News.tsx`, the face guard's `overlayZones` and nothing else, so change geometry there only. Automatic: captions above the bottom safe zone (or mid-frame), the headline card anchored by its bottom edge right above the captions (about one third from the bottom, growing upwards, because the top of a picture is where faces are) or in the bottom-caption slot when the captions are in the upper half; on the closing scene the outro sits above the captions and the headline above the outro. Manual (px of the 1080×1920 frame, null = automatic): `headline.x` = left edge, `headline.y` = bottom edge, `caption.x` = centre of the block, `caption.y` = its bottom edge; manual captions move the automatic headline with them. With `caption.align: "left"` the caption's `x` is its left edge instead of its centre. The hook headline is `HOOK_HEADLINE_SCALE` × the kit's size. 0.9.0: headlines (“tiêu đề”) default to 72 px so they read bigger than captions (“phụ đề”, 64 px); the form offers `HEADLINE_FONT_RANGE` 48–160 above `CAPTION_FONT_RANGE` 28–96 (the schema still parses smaller stored headlines), and a timeline with no `headline` at all keeps the legacy 54 px. Both text boxes have a per-kit `shadow` `{ colour, blur, x, y }` (`boxShadowCss`; headline default = the former hard-coded shadow, caption default = transparent = none). Remotion passes stored props without zod defaults, so the composition must tolerate every newer brand / scene field being absent (`textLayout` takes optionals). 0.10.0: credits. Each shot draws its own media credit (`shots[].credit`, "Ảnh: VnExpress" / "Video: … / Pexels") bottom-left for the length of the shot (`CreditLine`, width `CREDIT_MAX_WIDTH`, gated by `brand.showSource`); the article is credited only in the outro of the closing scene (`sourceDisplay(timeline.source)`: outlet name or host + URL without scheme, always shown, `OUTRO_HEIGHT` 220), and `timeline.attribution` now carries only the music (older timelines still list media credits there). The old always-on "Nguồn: <outlet>" line is gone. 0.11.0 / 0.12.0: landscape stills and clips are never cover-cropped. `News.tsx` measures each still / clip (`useMediaSize`: image load or video metadata, `delayRender`, cached per URL); a picture or clip wider than tall is drawn full width on a blurred, darkened copy of itself, centred on the upper-third line (`landscapeLayout` in `schema.ts`, pushed down only by the top safe zone), (`LandscapeFrame`; the clip is decoded twice, backdrop + front, inside the same `Loop`), stills with a gentle Ken Burns (`LANDSCAPE_KEN_BURNS`, ≤ 3 % per edge) and `focus` ignored, clips without; portrait / square media keep the cover fit (+ face-guard crop for stills). `frameStill` mirrors this (`frameLandscape`): no crop to choose, it only flags faces an overlay would cover. 0.13.0: caption line breaks are planned, never the browser's. Three rules: no line (and no chunk) of a single word unless the sentence is one word; the last word of a sentence never shares a line with the start of the next; a compound word / name / figure stays on one line. `media/captions.ts` `chunkCaptions` partitions each sentence as a whole (cheapest split, breaks at clause punctuation preferred, one word over the budget rather than a lone word), `media/compounds.ts` `markCompounds` sets `words[].j` (joined to the next word) from the Viet74K word list (`vi-compounds.ts`, generated, GPL-2.0, ~430 KB, so import it only where captions are built: never from a page's first-load bundle; add missing words to `EXTRA_COMPOUNDS`), capitalised runs (names) and number + unit; `buildTimeline` marks hand-edited chunks too. `captionLines` in `schema.ts` (pure, tested from the web app) turns a caption's words into one or two lines of unbreakable units, and `News.tsx` draws each line as an inline-block: both share a row when they fit, else the row wraps between them. Timelines stored before 0.13.0 have no `j` and still get the no-lone-word break. 0.14.0: the outro leaves out the source lines when `source.name` / `source.url` are empty (content typed in without a link). 0.15.0: motion graphics. Two new visual kinds (`isGraphicVisual`): `motion` = a `MotionSpec` (`packages/video/src/motion.ts`: beats of typed elements – kicker, title, text, stat count-up, bars, list, quote, timeline, compare, icon, image – with mood / background) drawn by `Motion.tsx` in `motionArea(brand, kind)` (clear of the top bar, captions and outro), and `hyperframes` = a HyperFrames composition (HTML + CSS + a paused GSAP timeline in `window.__timelines.shot`, github.com/heygen-com/hyperframes format) stored inline and drawn by `HyperFramesShot.tsx` in a sandboxed `srcdoc` iframe (`hyperframesDocument`: CSP without `connect-src`, pinned GSAP 3.13.0 from jsDelivr, brand CSS variables, `{{image:N}}` placeholders, a seek bridge; the component holds every frame with `delayRender` until the page answers `hf-seeked`). Both carry `images` as R2 keys (resolved in `timeline-resolve.ts` / the editor's `resolveForPlayer`), have no credit, no punch-in, no darkening gradient, and a scene whose shots are all graphics hides its headline card. `NewsMotionSample` is a Studio-only composition for them. 0.16.0: hand-drawn photos. An image visual may carry `sketch: { style }` (`SKETCH_STYLES` pencil / ink / colour, `sketchSchema` in `schema.ts`): the shot opens on the photo and a ragged pencil edge sweeps across it (`sketchTiming`: photo ~30 %, sweep ≤ 1 s, drawing for the rest), leaving a drawing of the same picture with the same crop and Ken Burns (`compositions/Sketch.tsx`: `Picture` draws a photo or its drawing in the box an `<Img>` would take – grey photo colour-dodged with its blurred negative + gamma, ink hatching in the shadows, a posterised colour wash for `colour`, paper grain, a seeded line boil every 4 frames; `SketchReveal` masks the drawing in). Done in the browser from the photo itself (no model, nothing invented), so face guard, credits and framing are unchanged; 0.16.1 / 0.16.2: the drawing is made once per picture on canvas 2D (`drawSketch`: colour dodge + self-multiply, wash, hatching, seeded grain, three wobble variants made by shifting strips along seeded waves; the sweep mask is a small canvas PNG – SVG turbulence is far too slow on a CPU) and each frame only shows one of the pre-drawn canvases with the shot's crop – the 0.16.0 version recomputed CSS blurs / blends / SVG turbulence on every frame, which Lambda's CPU-only Chrome could not do in 240 s per 60-frame chunk (renders timed out); keep per-frame work out of `Sketch.tsx`. - Originality (Meta's original content guidelines: footage the Page did not make, re-posted with only minor edits – captions, borders, music, speed, a voice-over that just describes it – is demoted, and a Page that keeps posting it loses recommendations and monetisation; TikTok / YouTube down-rank reused content too): `media/originality.ts` holds the app's own limits, since Meta publishes none: third-party *video* footage (provider `yt-dlp` / `yt-capture` = web video and a video project's source, `url` clips) at most `MAX_THIRD_PARTY_VIDEO_SHARE` (½) of the running time and never more than `MAX_THIRD_PARTY_RUN_SEC` (10 s, two shots) in a row. News stills, licensed stock and our own media (graphics, AI stills, uploads, solid cards) are not counted. The build applies them while flag `originality_guard` is on (default on; off = the earlier behaviour): a web video gives at most two segments, tier 2 places web video only within `thirdPartyVideoBudget`, a scene's shots are reordered by `spreadThirdParty` (carrying the run across scenes), a video project's source takes the `thirdPartyVideoMask` slots, and `build_json.originality` records the limits and `originalityReport` of the cut. The editor's `checks.originality` reports the same two limits for any cut (sources from the options' providers). On desktop the panel column (rail: click the open panel's icon, the bottom toggle or ⌘B) and the inspector (its header button or ⌥⌘B; collapsed = a 44 px strip that reopens it) collapse to give the preview room; opening a panel / tab from anywhere (`ui.setPanel` / `ui.setTab`, a check's fix) shows its column again. Panel, inspector tab, overlay and collapse choices are remembered per browser (localStorage, convenience only).
- Voice-over rewrites (`lib/llm/rewrite.ts`, `MODELS.rewrite` = `claude-opus-5-5`, effort `medium`, adaptive thinking, structured output, refusal fallback): modes `shorter`, `faithful` (uses the scene's faithfulness note / evidence) and `custom` (the editor's direction); the article text (≤ 24 000 chars) is always sent so a rewrite cannot add facts. Action `rewriteSceneVoiceover` only returns a suggestion (cost recorded, `scene.rewrite_suggested` logged); the editor puts it in the scene's voice-over draft and the user re-voices it (`regenerateScene` `what: "voice"`).
- Approval: `projects.approved_timeline_id` is the only "final" marker; a render advances the state to `rendered` only for that version. Publisher-only actions check `canApprove`.
- Publishing: one `publications` row per attempt (`idempotency_key` = render + channel + attempt; retry bumps `attempts` and re-keys the same row). Only the finished render of the approved timeline can be published; `platform_post_id` is written in the same step as the upload; `metadata.handles` carries per-platform ids while processing. Channel tokens are Vault secrets named `channel:<id>` (never in tables); use `channelAccessToken()` which refreshes on demand. Platform errors: throw `PlatformError(msg, permanent)`; permanent ones become `NonRetriableError`. YouTube quota units go to `usage_costs` as provider `youtube_api`.
