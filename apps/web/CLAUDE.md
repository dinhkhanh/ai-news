# ai-news

Internal app: news article URL → short vertical video → Facebook Reels / TikTok / YouTube Shorts.
Plan of record: `docs/PLAN.md`. Setup runbook: `docs/SETUP.md`. External filings: `docs/REQUESTS.md`.

## Layout
- `apps/web` – Next.js 16 (App Router, `src/`), Better Auth, Drizzle, Inngest, admin CMS at `/admin`.
  - `src/lib/fetch` – extraction chain (Browser Rendering → HTTP → Firecrawl → manual), Readability on linkedom, flags. A provider that errors, is blocked, or returns < 120 words hands over to the next one, in auto mode and in the manual “Lấy lại” re-fetch alike (`fetchOrder`: the picked provider only goes first). “Blocked” = `blocked.ts` `detectBlock` (pure, tested): refusal status (401/403/429/451/503…), interstitial title, vendor challenge markup (Cloudflare, DataDome, PerimeterX, Imperva, AWS WAF, Sucuri, Akamai), wall phrases (en + vi), redirect to a login/consent/captcha URL; all only below 300 extracted words. A wall is never kept as the article; a paywall teaser (< 300 words) stays a candidate while the other providers are tried. `attempts[].blocked` lands in the `article.fetched` activity payload.
  - `src/lib/llm` – Anthropic client (Vault key, spend cap, cost rows), structured-output schemas, template rendering, script / faithfulness / classify calls.
  - `src/lib/prompts/defaults.ts` – built-in templates (also seeded by migration 0003); admin versions in `prompt_templates` override them.
  - `src/lib/media` – phase 3: `tts.ts` (Google TTS + STT word timings), `stock.ts` (Pexels/Pixabay), `broll.ts` (per-scene search → Haiku rank → download, shared by build + regenerate), `rank.ts` (Haiku ranks B-roll thumbnails; `assignImages` maps article/related images to scenes, each once), `related.ts` (other outlets' images for the same story: Firecrawl search → Bing News RSS, plain HTTP fetch, stored as `article`/`related` assets), `generate.ts` (AI stills: `gemini-3.1-flash-image` on Vertex via `generateContent`, global endpoint, 9:16 1K, SA auth + project id from the `google_veo` integration; gated by flag `ai_media`, the integration spend cap and the daily `ai_media` quota), `webvideo.ts` (same-story footage from video sites: media-Lambda `web-video-search` = yt-dlp `ytsearch` + video-page URLs from Firecrawl search, metadata only; picked videos are downloaded section-only via `web-video`, stored as `web_video` assets, provider `yt-dlp`; flag `web_video_downloader`), `tab-capture.ts` (browser-only fallback for YouTube picks the Lambda cannot download because YouTube bot-checks AWS IPs: plays the official embed in the editor's tab and records it with `getDisplayMedia` + Region Capture + `MediaRecorder`, Chromium only, real time; `web-capture-panel.tsx` runs it, `registerWebCapture` normalises the upload with the Lambda `transcode` action into a `web_video` asset, provider `yt-capture`; the build lists such picks in `build_json.webVideo.pending`), `visual-plan.ts` (pure: the sourcing priority `VISUAL_TIERS` / `TIER_RANK` = article → related = web_video → stock → ai, capacity-aware `allocate` (a video = one shot per 5 s segment), `videoSegments`, `shortfall`, `splitBudget`; tested), `framing.ts` + `faces.ts` (face guard, flag `face_guard`: `faces.ts` runs Cloud Vision `FACE_DETECTION` once per still and keeps size + boxes in `assets.meta.frame`; `framing.ts` is pure and tested: `overlayZones` mirrors the overlay layout of `News.tsx`, `frameStill` picks the crop `focus` (pan, ≤ 1.3 zoom, Ken Burns off if needed) so faces are not cropped, not under text / platform UI, and centred on the upper-third line, else `ok: false`), `music.ts` (Mubert v3 + library), `brand.ts` (kits: `listBrandKits`, `loadBrand(ctx, kitId)` = the project's kit → workspace default → platform look, `chooseBrandKit` = Haiku match of the article against each kit's name / description / keywords with the pure keyword scorer of `brand-match.ts` as fallback; `png.ts` vets an overlay upload from its first bytes; both pure helpers are tested), `timeline.ts` (pure builder, R2 keys in `src`; `shotsNeeded`/`layoutShots` cut every scene into ≤ 5 s shots) + `timeline-resolve.ts` (presigned URLs for Lambda / preview); phase 4: `editor.ts` (pure editor document ⇄ timeline, `audioSignature`, `describeChanges`, legacy reconstruction) + `remix.ts` (media Lambda mix for a document). Pure helpers `pronounce.ts`, `align.ts`, `captions.ts`, `editor.ts` have tests.
  - `src/lib/publish` – phase 5: `platforms.ts` (pure: platform catalogue + limits, metadata defaults with attribution/disclosure, idempotency key, TikTok chunk plan, Vietnam datetime parsing; tested), `state.ts` (signed OAuth state; tested), `oauth.ts` (authorize URLs, code exchange → discovered channels, Vault token store `channel:<id>`, refresh, probe), `youtube.ts` / `meta.ts` / `tiktok.ts` (`PlatformClient`: start / check / analytics), `service.ts` (publication lifecycle shared by the Inngest function, the crons and admin actions). OAuth routes under `src/app/api/channels/oauth/[provider]`.
  - `src/lib/review.ts` – phase 4: `saveTimelineVersion` (validate doc + keys, re-mix if needed, new version with parent/kind/changes, clears approval, optimistic lock on base version), `canApprove`, faithfulness override check.
  - `src/components/editor/*` – client editor (`editor-loader.tsx` dynamic-imports it with `ssr: false` because it bundles the Remotion composition + Player): Player preview, dnd-kit scene track, inspector, comments. `review-panel.tsx` is shared with the project page.
  - `src/inngest/functions` – `fetch-article`, `generate-script`, `run-prompt-eval`, `prepare-assets`, `regenerate-scene`, `render-project`, `publish-publication` (+ crons in `publish-crons.ts`: processing poll, daily analytics, token refresh; phase 1 `test-render`).
- `packages/video` – Remotion compositions (`News` renders timeline JSON v1 from `src/schema.ts`, shared with the web app via `@ai-news/video/schema`) + Lambda deploy script (`ap-southeast-1`, output to R2). Bump the package version before `lambda:deploy` so the site name changes.
- `packages/media-lambda` – FFmpeg/yt-dlp Lambda (container image, AWS SAM): probe / loudnorm / duck / cover / mix / web-video (section-only download with `trim`) / transcode (uploaded recording → CFR 30 H.264, no audio) / web-video-search (yt-dlp metadata; parsers in `webvideo.ts`, tested). Keep `src/types.ts` in sync with `apps/web/src/lib/media-lambda.ts`; redeploy (`deploy.sh`) after changing the handler. The same handler also ships as a self-hosted HTTP API for a machine on a regular ISP line (office Synology NAS), because YouTube blocks datacenter IPs: `src/server.ts` (bearer token, `GET /health`, `POST /invoke`), `src/server-validate.ts` (tested: only search + trimmed downloads of known video sites, only web-video R2 keys), `Dockerfile.nas` (uses yt-dlp's ffmpeg builds; the static John Van Sickle ffmpeg segfaults on network input on Debian), `build-nas.sh` → `dist/nas/*.tar`. The app routes `web-video` downloads there via `invokeWebVideo` when `WEB_VIDEO_API_URL` / `WEB_VIDEO_API_TOKEN` are set, else (or when unreachable) to the Lambda.
- `infra/` – R2 bucket/lifecycle scripts, IAM policy.

## Commands
- `pnpm dev` – web app. `pnpm --filter web inngest:dev` – Inngest dev server.
- `pnpm typecheck` / `pnpm lint` / `pnpm test` – all packages (CI runs these).
- `pnpm db:generate` after schema edits (CI fails if a migration is missing). `pnpm db:migrate` applies with `DATABASE_DIRECT_URL`.
- `pnpm --filter @ai-news/video lambda:deploy` – Remotion function + site. Prints env vars.

## Rules
- Output spec is fixed (1080×1920, 30 fps, CRF 18, -14 LUFS). Never trade quality for cost.
- Every user/admin action calls `logActivity`; every paid call calls `recordUsageCost`.
- Org-scoped queries go through `withOrgContext`; admin/cross-workspace through `withServiceContext`.
- Admin CMS pages read through `src/lib/admin-data.ts`: one `SECURITY DEFINER` SQL function per page (migrations 0010 + 0013) returning the page as jsonb with camelCase keys, dates revived in the loader. A round-trip to the pooler is ~50 ms and a `withServiceContext` read costs four, so do not go back to per-table queries there. New functions in `public` must `revoke` from `anon` / `authenticated` / `service_role` by name (Supabase grants them EXECUTE by default, which publishes the function on the REST API) and grant `ai_news_app`; `migrations.test.ts` checks the grants and runs every function.
- The app's Postgres pool (`src/db/index.ts`) runs with `max_pipeline: 0` plus `patches/postgres@*.patch`: postgres.js pipelining through the Supavisor transaction pooler loses replies and hangs pages forever. Keep both when upgrading `postgres`; any new long-lived client on `DATABASE_URL` with `max` > 1 needs the same option.
- Secrets: deployment credentials in Vercel env; admin-editable keys and channel tokens in Supabase Vault (never in tables).
- Inngest v4: triggers in options, `eventType()` for typed events, keep `checkpointing.maxRuntime` below the route `maxDuration`. Set `projects.busy_step` (+ `busy_progress: startProgress()`) when a step is queued, call `reportProgress`/`tickProgress` (`src/lib/progress.ts`) *inside* each `step.run` body, and clear both in the function and in `onFailure`; the UI treats a flag older than 15 min as stale. Pages never poll by re-rendering: `<PipelineStatus>`/`<ProjectsWatcher>` poll `/api/projects/status` and call `router.refresh()` only when the status `rev` changes.
- Claude calls: `claude-opus-5` for script/faithfulness (adaptive thinking, structured outputs via `client.beta.messages.parse`, cached system blocks, server-side refusal fallback), `claude-haiku-4-5` for classification. Map billing/auth/400 errors to `NonRetriableError` (`isPermanentLlmError`).
- Pure helpers that need unit tests live outside `server-only` modules (`src/lib/url.ts`, `fetch/readability.ts`, `llm/render.ts`, `llm/schemas.ts`, `eval-summary.ts`, `text-match.ts`, `media/{pronounce,align,captions,timeline,visual-plan,framing}.ts`).
- Timeline JSON stores R2 keys, never URLs; presign only in `timeline-resolve.ts` right before a render (and `presignMap` for the editor preview). Project media lives under `media/<org>/<project>/` (12 mo), raw renders under `tmp/` (24 h), finals under `renders/` or `pinned/`.
- Timeline versions are immutable: never update `timelines.json`; every change goes through `saveTimelineVersion` (new row, `parent_id`, `changes`). Editing the composition's props means editing `packages/video/src/schema.ts` *and* `src/lib/media/editor.ts`/`timeline.ts`; bump `packages/video` and redeploy the site when the composition itself changes (0.3.0 added preview audio + `coverAtSec`; 0.4.0 added `scenes[].shots`; 0.5.0 added the image `focus`; 0.6.0 added the brand overlay: `brand.overlaySrc` / `overlayLayer` + `scenes[].overlay`; 0.7.0 moved the headline to the lower third and added `brand.logoMotion`). Never deploy twice under one version: the site name comes from the version, so a second deploy overwrites the first and there is nothing to roll back to. 0.8.0 added per-kit text settings: `brand.headline` `{ fontSize, x, y }` and `brand.caption.x / y`. Text layout: one function, `textLayout(brand, kind)` in `packages/video/src/schema.ts`, used by `News.tsx`, the face guard's `overlayZones` and nothing else, so change geometry there only. Automatic: captions above the bottom safe zone (or mid-frame), the headline card anchored by its bottom edge right above the captions (about one third from the bottom, growing upwards, because the top of a picture is where faces are) or in the bottom-caption slot when the captions are in the upper half; on the closing scene the outro sits above the captions and the headline above the outro. Manual (px of the 1080×1920 frame, null = automatic): `headline.x` = left edge, `headline.y` = bottom edge, `caption.x` = centre of the block, `caption.y` = its bottom edge; manual captions move the automatic headline with them. With `caption.align: "left"` the caption's `x` is its left edge instead of its centre. The hook headline is `HOOK_HEADLINE_SCALE` × the kit's size. 0.9.0: headlines (“tiêu đề”) default to 72 px so they read bigger than captions (“phụ đề”, 64 px); the form offers `HEADLINE_FONT_RANGE` 48–160 above `CAPTION_FONT_RANGE` 28–96 (the schema still parses smaller stored headlines), and a timeline with no `headline` at all keeps the legacy 54 px. Both text boxes have a per-kit `shadow` `{ colour, blur, x, y }` (`boxShadowCss`; headline default = the former hard-coded shadow, caption default = transparent = none). Remotion passes stored props without zod defaults, so the composition must tolerate every newer brand / scene field being absent (`textLayout` takes optionals). /app/brand shows a live preview (`brand-preview.tsx`, lazy-loaded): the real `News` composition in the Player on a sample story, rebuilt from the form's current values on every `input` / `change` event (`ColourField` dispatches one from its hidden input); new form fields must be added to `brandFromForm` there as well as to `saveBrandKit`.
- Visuals: a scene is `visual` (first shot) + `shots[]`; the builder splits the scene time equally, so a scene needs `shotsNeeded(voiceMs)` pictures for the ≤ 5 s cadence, and a picture must not repeat within a video (`prepare-assets` assigns each image once; the editor warns). Sourcing priority is fixed (`media/visual-plan.ts`): the article's own images → other outlets' images of the same story and same-story clips from video sites (equal rank; yt-dlp on the media Lambda, flag `web_video_downloader`, only the picked 5 s segments are downloaded, shots use `trimStartSec` = segment × 5) → free stock (Pexels/Pixabay) → AI-generated stills; each tier is only consulted for the shots the earlier tiers left open, and a scene's shots are ordered by tier. AI stills need flag `ai_media` + the `google_veo` integration, cost one `quota.ai_media` event each (max 8 per build) and set `projects.ai_disclosure`. Face guard (`media/framing.ts`, flag `face_guard`): article / related stills are scanned before placement; `allocateChecked` drops a still that fails in its scene from the whole pool so another candidate or a later tier takes the shot, and a rejected still only returns (last in its scene, `build_json.framing.forced`) when no tier could fill it. The passing crop is stored on the image visual as `focus` (+ `kenBurns`), which `News.tsx` applies; the inspector re-runs the pure guard on swap / headline edit / upload and warns. Videos and AI stills are not scanned. If overlay geometry in `News.tsx` or `SAFE_ZONES` changes, update `overlayZones`. A B-roll regeneration in the editor follows the same tail: stock, then AI when stock has nothing. Uploads go browser → presigned PUT → R2 (`createUploadUrl`/`registerUpload`; bucket CORS from `infra/r2/cors.json`, add the production origin), URL imports go through `importVisualFromUrl` (server download, 80 MB cap). Both become `upload` assets under `media/<org>/<project>/uploads/`.
- Brand kits: a workspace has several named kits (`/app/brand?kit=<id>`), exactly one default (partial unique index, migration 0014). A project's kit is `projects.brand_kit_id` with `brand_kit_source`: `manual` (picked at creation or in the “Dựng video” form; never overwritten) or `auto` (`fetch-article` step `brand-kit`, reason in `brand_kit_reason`); null = default. Kits with `auto_match = false` are only ever picked by hand. The kit is copied into the editor document at build time, so stored versions never change when a kit is edited; the editor can swap the embedded copy for any current kit (a new version, no re-mix). The overlay is a full-frame 1080×1920 transparent PNG per kit under `library/brand/<org>/overlay-<kit>-*.png`, uploaded browser → presigned PUT and then verified by `registerOverlay` (PNG, exact size, can be transparent; rejected files are deleted). `News.tsx` draws it for the whole length of every scene with `overlay !== false`, without the scene fade, either under the text layers (`under_text`) or above everything (`top`). Old logo / overlay files are never deleted because timeline versions keep referencing their keys; `assertKeysAllowed` rejects `library/brand/` keys of another workspace. The overlay's opaque areas are not yet part of `overlayZones` (face guard).
- Brand colours are CSS hex, `#rrggbb` or `#rrggbbaa` when translucent (`src/lib/colour.ts`, pure + tested, also reads the `rgba()` older kits hold); the picker at /app/brand (`colour-field.tsx`) = native colour input + opacity slider + hex field, and every colour including the caption background is editable. The composition uses them as plain CSS, so never do string maths on a colour (no appending alpha digits). Logo motion is per kit (`brand_kits.logo_motion` → `brand.logoMotion`, `LOGO_MOTIONS`: flip / tilt / spin / pulse / none, migration 0015): an entrance at the start, then a 0.9 s accent every `LOGO_MOTION_PERIOD_SEC`; timelines without the field render the default `flip`.
- Logos belong to channels, not kits (migration 0017): a kit is one look shared by every social channel, `channels.logo_path` (uploaded at /admin/channels, `src/lib/media/logo.ts`) is what a channel's videos carry. `projects.logo_channel_id` is chosen in the new-project form; timelines always embed the *kit's* logo (preview at /app/brand + fallback), and `render-project` swaps in the channel's logo on the copy sent to Lambda: the render's own choice (event `logoChannelId`, `"kit"` = the kit's logo) → the project's channel → the embedded kit logo; `renders.logo_channel_id` / `logo_path` record what was drawn. The editor preview does the same swap (`previewLogo`). One approved version can therefore be rendered once per channel (“Kết xuất lại … với logo kênh khác” on the project page), and the publish form picks the finished render whose logo matches the target channel, warning when there is none.
- Voice: platform presets from migration 0008 (Fenrir 1.22 default, Puck 1.20, Charon/Kore 1.15); script template v2 (punchy) is promoted by the same migration only when the admin never created a version. Keep `src/lib/prompts/defaults.ts` in sync with the seeded text.
- Feature flags: a flag without a `feature_flags` row takes its catalogue default (`FEATURE_FLAGS[].defaultOn` → `flagDefault`, used by `flags.ts` and /admin/integrations); only `face_guard` is on by default (migration 0018 also switches on an existing row). The inspector's “Tự căn khuôn mặt” button (`analyseVisual`) is the manual trigger for one picture: faces are detected once (`assets.meta.frame`, also for uploads / stock / AI stills the build never scans), the parent keeps them on the option (`onOptionFramed`) and the pure guard sets `focus` / `kenBurns` for that scene's overlays.
- Rendering is requested through one helper, `src/lib/render-request.ts` `queueRender` (busy lock, `render_minutes` quota, activity rows), from the project page (`requestRender`) and from the editor's export panel (`components/editor/export-panel.tsx` → `renderTimeline`; with unsaved edits it saves a new version first and renders that one; the header `<PipelineStatus>` reloads the page when the render ends). QA override: event field `skipQa` makes `render-project` keep the probe result in `qa_json` (+ `overridden`, `overriddenBy`) but finish as `done`; `queueRender` only accepts it when that version already has a `qa_failed` render, the UI offers it on the newest `qa_failed` row of a version (same version + logo) and marks such renders “QA bị bỏ qua”.
- Approval: `projects.approved_timeline_id` is the only "final" marker; a render advances the state to `rendered` only for that version. Publisher-only actions check `canApprove`.
- Publishing: one `publications` row per attempt (`idempotency_key` = render + channel + attempt; retry bumps `attempts` and re-keys the same row). Only the finished render of the approved timeline can be published; `platform_post_id` is written in the same step as the upload; `metadata.handles` carries per-platform ids while processing. Channel tokens are Vault secrets named `channel:<id>` (never in tables); use `channelAccessToken()` which refreshes on demand. Platform errors: throw `PlatformError(msg, permanent)`; permanent ones become `NonRetriableError`. YouTube quota units go to `usage_costs` as provider `youtube_api`.
- Next 16: `proxy.ts` (not middleware), route handlers under `src/app/api`. Read `apps/web/node_modules/next/dist/docs` before using unfamiliar APIs.
