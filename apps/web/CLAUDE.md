# ai-news

Internal app: news article URL → short vertical video → Facebook Reels / TikTok / YouTube Shorts.
Plan of record: `docs/PLAN.md`. Setup runbook: `docs/SETUP.md`. External filings: `docs/REQUESTS.md`.

## Layout
- `apps/web` – Next.js 16 (App Router, `src/`), Better Auth, Drizzle, Inngest, admin CMS at `/admin`.
  - `src/lib/fetch` – extraction chain (Browser Rendering → HTTP → Firecrawl → manual), Readability on linkedom, flags. A provider that errors, is blocked, or returns < 120 words hands over to the next one, in auto mode and in the manual “Lấy lại” re-fetch alike (`fetchOrder`: the picked provider only goes first). “Blocked” = `blocked.ts` `detectBlock` (pure, tested): refusal status (401/403/429/451/503…), interstitial title, vendor challenge markup (Cloudflare, DataDome, PerimeterX, Imperva, AWS WAF, Sucuri, Akamai), wall phrases (en + vi), redirect to a login/consent/captcha URL; all only below 300 extracted words. A wall is never kept as the article; a paywall teaser (< 300 words) stays a candidate while the other providers are tried. `attempts[].blocked` lands in the `article.fetched` activity payload.
  - `src/lib/llm` – Anthropic client (Vault key, spend cap, cost rows), structured-output schemas, template rendering, script / faithfulness / classify calls.
  - `src/lib/prompts/defaults.ts` – built-in templates (also seeded by migration 0003); admin versions in `prompt_templates` override them.
  - `src/lib/media` – phase 3: `tts.ts` (Google TTS + STT word timings), `stock.ts` (Pexels/Pixabay), `broll.ts` (per-scene search → Haiku rank → download, shared by build + regenerate), `rank.ts` (Haiku ranks B-roll thumbnails; `assignImages` maps article/related images to scenes, each once), `related.ts` (other outlets' images for the same story: Firecrawl search → Bing News RSS, plain HTTP fetch, stored as `article`/`related` assets), `generate.ts` (AI stills: `gemini-3.1-flash-image` on Vertex via `generateContent`, global endpoint, 9:16 1K, SA auth + project id from the `google_veo` integration; gated by flag `ai_media`, the integration spend cap and the daily `ai_media` quota), `webvideo.ts` (same-story footage from video sites: media-Lambda `web-video-search` = yt-dlp `ytsearch` + video-page URLs from Firecrawl search, metadata only; picked videos are downloaded section-only via `web-video`, stored as `web_video` assets, provider `yt-dlp`; flag `web_video_downloader`), `tab-capture.ts` (browser-only fallback for YouTube picks the Lambda cannot download because YouTube bot-checks AWS IPs: plays the official embed in the editor's tab and records it with `getDisplayMedia` + Region Capture + `MediaRecorder`, Chromium only, real time; `web-capture-panel.tsx` runs it, `registerWebCapture` normalises the upload with the Lambda `transcode` action into a `web_video` asset, provider `yt-capture`; the build lists such picks in `build_json.webVideo.pending`), `visual-plan.ts` (pure: the sourcing priority `VISUAL_TIERS` / `TIER_RANK` = article → related = web_video → stock → ai, capacity-aware `allocate` (a video = one shot per 5 s segment), `videoSegments`, `shortfall`, `splitBudget`; tested), `framing.ts` + `faces.ts` (face guard, flag `face_guard`: `faces.ts` runs Cloud Vision `FACE_DETECTION` once per still and keeps size + boxes in `assets.meta.frame`; `framing.ts` is pure and tested: `overlayZones` mirrors the overlay layout of `News.tsx`, `frameStill` picks the crop `focus` (pan, ≤ 1.3 zoom, Ken Burns off if needed) so faces are not cropped, not under text / platform UI, and centred on the upper-third line, else `ok: false`), `music.ts` (Mubert v3 + library), `brand.ts` (kits: `listBrandKits`, `loadBrand(ctx, kitId)` = the project's kit → workspace default → platform look, `chooseBrandKit` = Haiku match of the article against each kit's name / description / keywords with the pure keyword scorer of `brand-match.ts` as fallback; `png.ts` vets an overlay upload from its first bytes; both pure helpers are tested), `timeline.ts` (pure builder, R2 keys in `src`; `shotsNeeded`/`layoutShots` cut every scene into ≤ 5 s shots) + `timeline-resolve.ts` (presigned URLs for Lambda / preview); phase 4: `editor.ts` (pure editor document ⇄ timeline, `audioSignature`, `describeChanges`, legacy reconstruction) + `remix.ts` (media Lambda mix for a document). Pure helpers `pronounce.ts`, `align.ts`, `captions.ts`, `editor.ts` have tests.
  - `src/lib/publish` – phase 5: `platforms.ts` (pure: platform catalogue + limits, metadata defaults with attribution/disclosure, idempotency key, TikTok chunk plan, Vietnam datetime parsing; tested), `state.ts` (signed OAuth state; tested), `oauth.ts` (authorize URLs, code exchange → discovered channels, Vault token store `channel:<id>`, refresh, probe), `youtube.ts` / `meta.ts` / `tiktok.ts` (`PlatformClient`: start / check / analytics), `service.ts` (publication lifecycle shared by the Inngest function, the crons and admin actions). OAuth routes under `src/app/api/channels/oauth/[provider]`. Channels are self-service: members connect and manage their own at `/app/channels` (start route without `?org=` = the active workspace, connector auto-granted), platform admins work across workspaces at `/admin/channels` (`?org=<id>`); `channel-access.ts` (pure, tested: `canConnectChannel` = any writer, `canManageChannel` = connector / workspace admin / platform admin) and `channel-ops.ts` (grant, revoke, pause, token check, disconnect, logo) are shared by both sets of server actions, so change channel behaviour there, not in the actions.
  - `src/lib/review.ts` – phase 4: `saveTimelineVersion` (validate doc + keys, re-mix if needed, new version with parent/kind/changes, clears approval, optimistic lock on base version), `canApprove`, faithfulness override check.
  - `src/components/editor/*` – client editor (`editor-loader.tsx` dynamic-imports it with `ssr: false` because it bundles the Remotion composition + Player): Player preview, dnd-kit scene track, inspector, comments. `review-panel.tsx` is shared with the project page.
  - `src/inngest/functions` – `fetch-article`, `generate-script`, `run-prompt-eval`, `prepare-assets`, `regenerate-scene`, `render-project`, `publish-publication` (phase 1 `test-render`). The recurring jobs (processing poll, daily analytics, token refresh, queue watchdog) are not Inngest functions: `src/lib/cron-jobs.ts` behind `/api/cron/<job>`, scheduled by pg_cron. `fetch-article` / `generate-script` are thin wrappers over `src/lib/pipeline`.
- `packages/video` – Remotion compositions (`News` renders timeline JSON v1 from `src/schema.ts`, shared with the web app via `@ai-news/video/schema`) + Lambda deploy script (`ap-southeast-1`, output to R2). Bump the package version before `lambda:deploy` so the site name changes.
- `packages/media-lambda` – FFmpeg/yt-dlp Lambda (container image, AWS SAM): probe / loudnorm / duck / cover / mix / web-video (section-only download with `trim`) / transcode (uploaded recording → CFR 30 H.264, no audio) / web-video-search (yt-dlp metadata; parsers in `webvideo.ts`, tested). Keep `src/types.ts` in sync with `apps/web/src/lib/media-lambda.ts`; redeploy (`deploy.sh`) after changing the handler. The same handler also ships as a self-hosted HTTP API for a machine on a regular ISP line (office Synology NAS), because YouTube blocks datacenter IPs: `src/server.ts` (bearer token, `GET /health`, `POST /invoke`), `src/server-validate.ts` (tested: only search + trimmed downloads of known video sites, only web-video R2 keys), `Dockerfile.nas` (uses yt-dlp's ffmpeg builds; the static John Van Sickle ffmpeg segfaults on network input on Debian), `build-nas.sh` → `dist/nas/*.tar`. The app routes every `web-video` download (build, editor paste, re-search) there via `invokeWebVideo` when `WEB_VIDEO_API_URL` / `WEB_VIDEO_API_TOKEN` are set, else (or when unreachable) to the Lambda; `invokeMediaLambda` refuses `web-video` at the type level so no download can skip the box. Searches / page lookups (`web-video-search`) may use the Lambda, which YouTube does not block for metadata.
- `infra/` – R2 bucket/lifecycle scripts, IAM policy.

## Rules
- Output spec is fixed (1080×1920, 30 fps, CRF 18, -14 LUFS). Never trade quality for cost.
- Every user/admin action calls `logActivity`; every paid call calls `recordUsageCost`.
- Org-scoped queries go through `withOrgContext`; admin/cross-workspace through `withServiceContext`.
- Authorisation lives next to the data, never only in a layout: Next renders a page segment without its layout when the request claims the layout is already mounted, and `src/proxy.ts` only looks for a session cookie. Every `/admin` page starts with `await requireAdmin()` and every admin action with `assertAdmin()` (`src/app/admin/page-guards.test.ts` fails otherwise); every `/app` page calls `requireWorkspace` / `requireSession` itself. Better Auth's `/organization/*` endpoints are closed in `hooks.before` except `ORG_ENDPOINTS_OPEN` (members and roles are managed in /admin/workspaces only; `kind` is not client input). A `next` / return parameter goes through `safeNextPath` (`src/lib/url.ts`). Security headers are set for every route in `next.config.ts` (`frame-ancestors 'none'`; there is no script CSP yet).
- Database access (migration 0021): the app is the only client, as role `ai_news_app`; the Supabase Data API roles (`anon`, `authenticated`, `service_role`) hold nothing in `public` and the default privileges no longer give them anything, so do not add supabase-js / REST access without granting on purpose. Every table has RLS on with policies for `ai_news_app` only: a new org-scoped table takes the `<table>_org_isolation` policy (helpers wrapped as `(select app_org_id())` so they run once per statement, because functions with a pinned `search_path` are not inlined), a new platform / auth table takes `<table>_app_only`. `migrations.test.ts` fails on a table without RLS or a policy, a grant to anyone but `postgres` / `ai_news_app`, and a function without `set search_path`.
- Admin CMS pages read through `src/lib/admin-data.ts`: one `SECURITY DEFINER` SQL function per page (migrations 0010 + 0013) returning the page as jsonb with camelCase keys, dates revived in the loader. A round-trip to the pooler is ~50 ms and a `withServiceContext` read costs four, so do not go back to per-table queries there. New functions in `public` must `revoke` from `anon` / `authenticated` / `service_role` by name (Supabase grants them EXECUTE by default, which publishes the function on the REST API) and grant `ai_news_app`; `migrations.test.ts` checks the grants and runs every function.
- The app's Postgres pool (`src/db/index.ts`) runs with `max_pipeline: 0` plus `patches/postgres@*.patch`: postgres.js pipelining through the Supavisor transaction pooler loses replies and hangs pages forever. Keep both when upgrading `postgres`; any new long-lived client on `DATABASE_URL` with `max` > 1 needs the same option.
- Secrets: deployment credentials in Vercel env; admin-editable keys and channel tokens in Supabase Vault (never in tables).
- Inngest v4: triggers in options, `eventType()` for typed events, keep `checkpointing.maxRuntime` below the route `maxDuration`. Set `projects.busy_step` (+ `busy_progress: startProgress()`) when a step is queued, call `reportProgress`/`tickProgress` (`src/lib/progress.ts`) *inside* each `step.run` body, and clear both in the function and in `onFailure`; the UI treats a flag older than 15 min as stale. Pages never poll by re-rendering: `<PipelineStatus>`/`<ProjectsWatcher>` poll `/api/projects/status` and call `router.refresh()` only when the status `rev` changes.
- Queue outages (Inngest, 2026-09-18): the bodies of `fetch-article` and `generate-script` live in `src/lib/pipeline/{fetch,script}.ts` and take a `PipelineSteps` (`steps.ts`): the Inngest function passes `durableSteps(step)`, a direct run passes `directSteps`, so change step logic there, never in the function file, and keep step results JSON-safe. Direct runs (`pipeline/direct.ts`, actions `fetchDirect` / `scriptDirect` / `pasteArticle`, run from `after()`; the project page has `maxDuration = 300`): `claimDirectRun` is a compare-and-set on `busy_progress.at`, allowed when the requested step was never started for `QUEUE_SLOW_MS` (90 s; `queuedForMs` = `at` still equals `startedAt`) or went stale; one provider only (`fetchOrder(method, true)`), no retries, `busy_progress.direct = true`. `<PipelineStatus>` shows `<QueueRescue>` in that state (buttons for `DIRECT_STEPS` = fetch + script; assets / render / publish are too long and can only wait); after a failed direct fetch `projects.inngest_run_id = "direct"` keeps the direct buttons on the fallback card. A manual paste is always a direct run. Every pipeline function's first step calls `eventSuperseded(event.ts, …)` (pure, tested, `project-state.ts`): an event older than the newest result of its step (article / script / `built` timeline / render of the same version + logo), or older than a direct run in progress, returns `{ skipped: "superseded" }` without touching the project, so a backlog draining after an outage redoes nothing (this also skips a dashboard replay of an old event). New pipeline functions need the same check before their first write. Recurring jobs are plain functions in `src/lib/cron-jobs.ts` behind `GET|POST /api/cron/<job>` (`Authorization: Bearer $CRON_SECRET`, closed when unset, 202 + `after()`, `?wait=1` = inline); the scheduler is Supabase pg_cron + pg_net (`infra/supabase/cron.sql`, applied by hand to production on 2026-09-19, not a migration; helper `public.ai_news_cron_call`, secret in Vault as `ai_news_cron_secret`; keep its schedules in sync with `CRON_JOBS`). There are no Inngest crons any more: a cron on Inngest stops with Inngest, and every Inngest run and step is a billed execution (Hobby = 50k / month, and execution *pauses* when it is used up, which looks exactly like an outage). Vercel is on the Hobby plan: a cron more often than daily in `vercel.json` fails the deployment. `queue-watchdog` (`src/lib/queue-health.ts`: `findStalledQueue`, status.inngest.com, one `queue.stalled` activity row + Slack message per 3 h) watches Inngest and must never run on it; /admin/health shows the same two signals.
- Claude calls: `claude-opus-5` for script/faithfulness (adaptive thinking, structured outputs via `client.beta.messages.parse`, cached system blocks, server-side refusal fallback), `claude-haiku-4-5` for classification. Map billing/auth/400 errors to `NonRetriableError` (`isPermanentLlmError`).
- Pure helpers that need unit tests live outside `server-only` modules (`src/lib/url.ts`, `fetch/readability.ts`, `llm/render.ts`, `llm/schemas.ts`, `eval-summary.ts`, `text-match.ts`, `media/{pronounce,align,captions,timeline,visual-plan,framing}.ts`).
- Timeline JSON stores R2 keys, never URLs; presign only in `timeline-resolve.ts` right before a render (and `presignMap` for the editor preview). Project media lives under `media/<org>/<project>/` (12 mo), raw renders under `tmp/` (24 h), finals under `renders/` or `pinned/`.
- Timeline versions are immutable: never update `timelines.json`; every change goes through `saveTimelineVersion` (new row, `parent_id`, `changes`). Editing the composition's props means editing `packages/video/src/schema.ts` *and* `src/lib/media/editor.ts`/`timeline.ts`; bump `packages/video` and redeploy the site when the composition itself changes (0.3.0 added preview audio + `coverAtSec`; 0.4.0 added `scenes[].shots`; 0.5.0 added the image `focus`; 0.6.0 added the brand overlay: `brand.overlaySrc` / `overlayLayer` + `scenes[].overlay`; 0.7.0 moved the headline to the lower third and added `brand.logoMotion`). Never deploy twice under one version: the site name comes from the version, so a second deploy overwrites the first and there is nothing to roll back to. 0.8.0 added per-kit text settings: `brand.headline` `{ fontSize, x, y }` and `brand.caption.x / y`. Text layout: one function, `textLayout(brand, kind)` in `packages/video/src/schema.ts`, used by `News.tsx`, the face guard's `overlayZones` and nothing else, so change geometry there only. Automatic: captions above the bottom safe zone (or mid-frame), the headline card anchored by its bottom edge right above the captions (about one third from the bottom, growing upwards, because the top of a picture is where faces are) or in the bottom-caption slot when the captions are in the upper half; on the closing scene the outro sits above the captions and the headline above the outro. Manual (px of the 1080×1920 frame, null = automatic): `headline.x` = left edge, `headline.y` = bottom edge, `caption.x` = centre of the block, `caption.y` = its bottom edge; manual captions move the automatic headline with them. With `caption.align: "left"` the caption's `x` is its left edge instead of its centre. The hook headline is `HOOK_HEADLINE_SCALE` × the kit's size. 0.9.0: headlines (“tiêu đề”) default to 72 px so they read bigger than captions (“phụ đề”, 64 px); the form offers `HEADLINE_FONT_RANGE` 48–160 above `CAPTION_FONT_RANGE` 28–96 (the schema still parses smaller stored headlines), and a timeline with no `headline` at all keeps the legacy 54 px. Both text boxes have a per-kit `shadow` `{ colour, blur, x, y }` (`boxShadowCss`; headline default = the former hard-coded shadow, caption default = transparent = none). Remotion passes stored props without zod defaults, so the composition must tolerate every newer brand / scene field being absent (`textLayout` takes optionals). 0.10.0: credits. Each shot draws its own media credit (`shots[].credit`, "Ảnh: VnExpress" / "Video: … / Pexels") bottom-left for the length of the shot (`CreditLine`, width `CREDIT_MAX_WIDTH`, gated by `brand.showSource`); the article is credited only in the outro of the closing scene (`sourceDisplay(timeline.source)`: outlet name or host + URL without scheme, always shown, `OUTRO_HEIGHT` 220), and `timeline.attribution` now carries only the music (older timelines still list media credits there). The old always-on "Nguồn: <outlet>" line is gone. 0.11.0 / 0.12.0: landscape stills and clips are never cover-cropped. `News.tsx` measures each still / clip (`useMediaSize`: image load or video metadata, `delayRender`, cached per URL); a picture or clip wider than tall is drawn full width on a blurred, darkened copy of itself, centred on the upper-third line (`landscapeLayout` in `schema.ts`, pushed down only by the top safe zone), (`LandscapeFrame`; the clip is decoded twice, backdrop + front, inside the same `Loop`), stills with a gentle Ken Burns (`LANDSCAPE_KEN_BURNS`, ≤ 3 % per edge) and `focus` ignored, clips without; portrait / square media keep the cover fit (+ face-guard crop for stills). `frameStill` mirrors this (`frameLandscape`): no crop to choose, it only flags faces an overlay would cover. 0.13.0: caption line breaks are planned, never the browser's. Three rules: no line (and no chunk) of a single word unless the sentence is one word; the last word of a sentence never shares a line with the start of the next; a compound word / name / figure stays on one line. `media/captions.ts` `chunkCaptions` partitions each sentence as a whole (cheapest split, breaks at clause punctuation preferred, one word over the budget rather than a lone word), `media/compounds.ts` `markCompounds` sets `words[].j` (joined to the next word) from the Viet74K word list (`vi-compounds.ts`, generated, GPL-2.0, ~430 KB, so import it only where captions are built: never from a page's first-load bundle; add missing words to `EXTRA_COMPOUNDS`), capitalised runs (names) and number + unit; `buildTimeline` marks hand-edited chunks too. `captionLines` in `schema.ts` (pure, tested from the web app) turns a caption's words into one or two lines of unbreakable units, and `News.tsx` draws each line as an inline-block: both share a row when they fit, else the row wraps between them. Timelines stored before 0.13.0 have no `j` and still get the no-lone-word break. 0.14.0: the outro leaves out the source lines when `source.name` / `source.url` are empty (content typed in without a link). /app/brand shows a live preview (`brand-preview.tsx`, lazy-loaded): the real `News` composition in the Player on a sample story, rebuilt from the form's current values on every `input` / `change` event (`ColourField` dispatches one from its hidden input); new form fields must be added to `brandFromForm` there as well as to `saveBrandKit`.
- Visuals: a scene is `visual` (first shot) + `shots[]`; the builder splits the scene time equally, so a scene needs `shotsNeeded(voiceMs)` pictures for the ≤ 5 s cadence, and a picture must not repeat within a video (`prepare-assets` assigns each image once; the editor warns). Sourcing priority is fixed (`media/visual-plan.ts`): the article's own images → other outlets' images of the same story and same-story clips from video sites (equal rank; yt-dlp on the media Lambda, flag `web_video_downloader`, only the picked 5 s segments are downloaded, shots use `trimStartSec` = segment × 5) → free stock (Pexels/Pixabay) → AI-generated stills; each tier is only consulted for the shots the earlier tiers left open, and a scene's shots are ordered by tier. AI stills need flag `ai_media` + the `google_veo` integration, cost one `quota.ai_media` event each (max 8 per build) and set `projects.ai_disclosure`. “What you hear is what you see”: the script LLM gives every scene `newsTerms` (1–3 news queries in the article’s language naming what that scene’s voice-over mentions: person, company, place, event; `brollTerms` stay generic English stock phrases). Tier 2 searches once per needy scene by its first `newsTerms` plus the story title once (`tier2Queries` in `visual-plan.ts`, capped at `MAX_TIER2_QUERIES`; `findRelatedImagesFor` / `findWebVideosFor` merge round-robin and dedupe), each candidate’s hint says which scene it was “found for” and the Haiku placement prefers it there. Political stories (`projects.political`, set by the fetch classification `political`, migration 0019) never use the stock or AI tiers (`tierAllowed`), in the build and in the editor’s re-search alike; the editor’s “Tìm hình mới” searches other outlets by the scene’s `newsTerms` first (face-guarded), then stock, then AI. Face guard (`media/framing.ts`, flag `face_guard`): article / related stills are scanned before placement; `allocateChecked` drops a still that fails in its scene from the whole pool so another candidate or a later tier takes the shot, and a rejected still only returns (last in its scene, `build_json.framing.forced`) when no tier could fill it. The passing crop is stored on the image visual as `focus` (+ `kenBurns`), which `News.tsx` applies; the inspector re-runs the pure guard on swap / headline edit / upload and warns. Videos and AI stills are not scanned. If overlay geometry in `News.tsx` or `SAFE_ZONES` changes, update `overlayZones`. A B-roll regeneration in the editor follows the same tail: stock, then AI when stock has nothing. Uploads go browser → presigned PUT → R2 (`createUploadUrl`/`registerUpload`; bucket CORS from `infra/r2/cors.json`, add the production origin), URL imports go through `importVisualFromUrl` (server download, 80 MB cap). Both become `upload` assets under `media/<org>/<project>/uploads/`. The same field also takes a video *page* (YouTube watch / shorts / youtu.be, TikTok, Facebook reels / watch, fb.watch, Vimeo, Dailymotion – `webVideoPageUrl` in `visual-plan.ts`) with a “từ … đến …” timecode range (`parseTimecode`, `manualSection`: default the first 20 s, at most `MAX_MANUAL_SECTION_SEC` 60 s, cut to the video’s length): `importWebVideo` resolves the page with yt-dlp (`web-video-search` on the Lambda, metadata only), downloads just that section through `storeWebVideo` (NAS API → Lambda, flag `web_video_downloader`) and stores a `web_video` asset credited to the uploader; a YouTube page the server cannot fetch comes back as a `PendingCapture` with `manual: { sceneId, shot }` that the editor adds to the “Ghi từ trình duyệt” panel, and the recording then replaces that one shot as a single clip.
- Project sources (`projects.source_kind`, migration 0022): `article` (a news link, the fetch chain), `video` and `text`. The new-project form (`app/app/new-project-source.tsx`) has “Dán link” / “Tự nhập nội dung”. A link is a `video` when `videoLinkKind` (`src/lib/video-source.ts`, pure, tested) says so: YouTube watch / shorts / youtu.be, TikTok, Facebook reel / watch / videos, fb.watch, Vimeo, Dailymotion, plus share links (vt / vm.tiktok.com, tiktok.com/t/, facebook.com/share/r|v/) that `resolveVideoLink` (`media/source-video.ts`) follows hop by hop, reading only `Location`; `videoPageUrl` is the canonical form stored in `url` and compared for duplicates. The fetch step of a `video` project reads title + caption with yt-dlp (`lookupVideo`, `web-video-search` via `invokeWebVideo`; the caption is `WebVideoCandidate.description`, which Lambda / NAS builds older than this change do not send, so the title is used), downloads the first `SOURCE_VIDEO_MAX_SEC` (120 s, the NAS limit) as a `web_video` asset with `meta.role = "source"` (`projects.source_video_asset_id`), and stores the caption as an *unconfirmed* article: the user writes the content (`MIN_CONTENT_WORDS.video` = 1 word) and confirms; auto mode waits and `confirmArticle` resumes it. `prepare-assets` then cuts every shot from that video, playing on continuously across scenes and starting over when the voice-over is longer (`sourceVideoShots`), and consults no other tier. A `text` project has no link (`url` null, allowed only for this kind by `projects_url_check`): its content is saved in the create request's `after()` as a manual, confirmed article (a direct run), there is nothing to re-fetch, the outro names no source (`source.url` "", composition 0.14.0) and the publish text has no source line. The script request tells Claude what a `video` / `text` project's text is (`sourceNote` in `llm/script.ts`, kept out of the cached system prefix). Use `projectLabel` (title → url → “Nội dung tự nhập”) wherever a project is named.
- Brand kits: a workspace has several named kits (`/app/brand?kit=<id>`), exactly one default (partial unique index, migration 0014). A project's kit is `projects.brand_kit_id` with `brand_kit_source`: `manual` (picked at creation or in the “Dựng video” form; never overwritten) or `auto` (`fetch-article` step `brand-kit`, reason in `brand_kit_reason`); null = default. Kits with `auto_match = false` are only ever picked by hand. The kit is copied into the editor document at build time, so stored versions never change when a kit is edited; the editor can swap the embedded copy for any current kit (a new version, no re-mix). The overlay is a full-frame 1080×1920 transparent PNG per kit under `library/brand/<org>/overlay-<kit>-*.png`, uploaded browser → presigned PUT and then verified by `registerOverlay` (PNG, exact size, can be transparent; rejected files are deleted). `News.tsx` draws it for the whole length of every scene with `overlay !== false`, without the scene fade, either under the text layers (`under_text`) or above everything (`top`). Old logo / overlay files are never deleted because timeline versions keep referencing their keys; `assertKeysAllowed` rejects `library/brand/` keys of another workspace. The overlay's opaque areas are not yet part of `overlayZones` (face guard).
- Brand colours are CSS hex, `#rrggbb` or `#rrggbbaa` when translucent (`src/lib/colour.ts`, pure + tested, also reads the `rgba()` older kits hold); the picker at /app/brand (`colour-field.tsx`) = native colour input + opacity slider + hex field, and every colour including the caption background is editable. The composition uses them as plain CSS, so never do string maths on a colour (no appending alpha digits). Logo motion is per kit (`brand_kits.logo_motion` → `brand.logoMotion`, `LOGO_MOTIONS`: flip / tilt / spin / pulse / none, migration 0015): an entrance at the start, then a 0.9 s accent every `LOGO_MOTION_PERIOD_SEC`; timelines without the field render the default `flip`.
- Logos belong to channels, not kits (migration 0017): a kit is one look shared by every social channel, `channels.logo_path` (uploaded at /app/channels by whoever manages the channel, or at /admin/channels; `src/lib/media/logo.ts`) is what a channel's videos carry. `projects.logo_channel_id` is chosen in the new-project form; timelines always embed the *kit's* logo (preview at /app/brand + fallback), and `render-project` swaps in the channel's logo on the copy sent to Lambda: the render's own choice (event `logoChannelId`, `"kit"` = the kit's logo) → the project's channel → the embedded kit logo; `renders.logo_channel_id` / `logo_path` record what was drawn. The editor preview does the same swap (`previewLogo`). One approved version can therefore be rendered once per channel (“Kết xuất lại … với logo kênh khác” on the project page), and the publish form picks the finished render whose logo matches the target channel, warning when there is none.
- Voice: platform presets from migration 0008 (Fenrir 1.22 default, Puck 1.20, Charon/Kore 1.15); script template v2 (punchy) is promoted by the same migration only when the admin never created a version. Keep `src/lib/prompts/defaults.ts` in sync with the seeded text.
- Workspace voices (migration 0023, `/app/voices`, any writer, not admin-only): a `voice_presets` row of the workspace with `model` = `GEMINI_TTS_MODEL` (`gemini-2.5-flash-tts`), one of `GEMINI_VOICES` and a style `prompt` (tone, pace, emotion; ≤ `VOICE_PROMPT_MAX`), saved under a name; “Nghe thử” (`previewVoice` → `synthesizeSample`, a WAV data URL, cost recorded) works on unsaved form values and on every saved voice. One workspace default per language (`voice_presets_one_default_idx`). Projects pick a voice at creation and in the “Dựng video” form (`projects.voice_preset_id`, `VoiceSelect`, checked by `findVoice`); the build and the editor’s re-voice call `loadVoicePreset(ctx, language, project.voicePresetId)`, which resolves with `pickVoice` (`media/voices.ts`, pure, tested): the project’s voice if it can read the story’s language (Gemini voices read both, classic voices only their own) → workspace default → platform default. Gemini-TTS goes through the same Cloud TTS client (`input.prompt` + `voice.modelName`, LINEAR16 24 kHz, no timepoints so STT aligns the words like Chirp) and bills tokens (`ttsCostUsd`: ~$0.015 per minute of audio). It needs the Agent Platform API (`aiplatform.googleapis.com`; Vertex AI was renamed Gemini Enterprise Agent Platform) on in the TTS service account’s project and the Agent Platform User role (`roles/aiplatform.user`) on that account (docs/SETUP.md); without them the call fails with a message saying so. Voices are not attached to brand kits.
- Feature flags: a flag without a `feature_flags` row takes its catalogue default (`FEATURE_FLAGS[].defaultOn` → `flagDefault`, used by `flags.ts` and /admin/integrations); `face_guard` (migration 0018) and `web_video_downloader` (migration 0020) are on by default; each migration also switches on the existing row once, and both stay admin toggles afterwards. The inspector's “Tự căn khuôn mặt” button (`analyseVisual`) is the manual trigger for one picture: faces are detected once (`assets.meta.frame`, also for uploads / stock / AI stills the build never scans), the parent keeps them on the option (`onOptionFramed`) and the pure guard sets `focus` / `kenBurns` for that scene's overlays.
- Rendering is requested through one helper, `src/lib/render-request.ts` `queueRender` (busy lock, `render_minutes` quota, activity rows), from the project page (`requestRender`) and from the editor's export panel (`components/editor/export-panel.tsx` → `renderTimeline`; with unsaved edits it saves a new version first and renders that one; the header `<PipelineStatus>` reloads the page when the render ends). QA override: event field `skipQa` makes `render-project` keep the probe result in `qa_json` (+ `overridden`, `overriddenBy`) but finish as `done`; `queueRender` only accepts it when that version already has a `qa_failed` render, the UI offers it on the newest `qa_failed` row of a version (same version + logo) and marks such renders “QA bị bỏ qua”.
- Approval: `projects.approved_timeline_id` is the only "final" marker; a render advances the state to `rendered` only for that version. Publisher-only actions check `canApprove`.
- Publishing: one `publications` row per attempt (`idempotency_key` = render + channel + attempt; retry bumps `attempts` and re-keys the same row). Only the finished render of the approved timeline can be published; `platform_post_id` is written in the same step as the upload; `metadata.handles` carries per-platform ids while processing. Channel tokens are Vault secrets named `channel:<id>` (never in tables); use `channelAccessToken()` which refreshes on demand. Platform errors: throw `PlatformError(msg, permanent)`; permanent ones become `NonRetriableError`. YouTube quota units go to `usage_costs` as provider `youtube_api`.
